# 麦麦点单参谋：凑券不凑亏

**吃什么、怎么选、要不要凑满减，让每个选择都有依据。**

麦麦点单参谋是配合官方麦当劳 MCP 使用的 Agent Skill：根据你选择的门店、预算和口味挑餐，比较优惠前后含费实付，并在分别确认后协助领券、创建待支付订单。非麦当劳官方产品。

项目由 Skill 和 Python 标准库内核组成。实时查询与工具调用交给你使用的 Agent 主机；本地代码负责报价校验、方案排序、差额计算和交易确认流程。

## 能帮你做什么

| 功能 | 你会得到什么 |
| --- | --- |
| 按预算选餐 | 在门店可售候选中筛选，展示餐品组成、完整报价及预算余量 |
| 三种角度比较 | 钱包优先按实付排序；营养目标按与指定热量的距离排序；口味优先按主动喜好匹配排序 |
| 随机选一个、再换一个 | 从符合约束的候选中抽取，跳过本轮已经展示的方案；没有合适选项时说明原因 |
| 排除不喜欢的餐品 | 明确不喜欢的标签从所有榜单与随机池中移除，不因价格便宜而重新推荐 |
| 判断凑券值不值 | 比较原车和加购后的完整实付，拆出商品、配送、其他费用及优惠各自的变化 |
| 比较同一购物车用券前后 | 保持门店、取餐方式、商品、规格和数量一致，再计算支出变化 |
| 解释推荐和未知项 | 展示匹配口味、热量目标偏差、价格来源与时间；缺营养、费用或优惠条件时明确说明 |
| 分步确认领券与下单 | 领券单独确认，刷新卡包并重算；具体订单再次确认，创建后读回状态，付款由你完成 |

比如，原车商品 30 元、配送 6 元，共 36 元；为了满减加购到 42 元，优惠 10 元、配送仍为 6 元，最后是 38 元。**券省了 10 元，实际却多付了 2 元。** 这是合成示例；真实比较需要两份完整报价和已核实的优惠条件。

## 直接这样问

> 一个人，到店自取，预算 40 元，喜欢鸡肉。给我省钱、接近 600 kcal 和合口味的选择，先不要领券或下单。

> 为了满减再加一份值不值？把配送费也算进去，告诉我最后多付还是少付。

> 不喜欢牛肉，刚才那份也先跳过。再随机换一个，没有符合条件的就告诉我。

通常先确定门店与需求，再查看候选和报价。需要领券时，会说明“绑定全部当前可领券”并等待确认；下单前会再次展示具体商品、规格、数量、优惠、费用和履约信息。推荐、领券、下单分别处理，不合并授权。

## 安装与接入

需要支持本地 Skill 和 MCP 的 Agent 主机，以及 Python 3.10+。Python 部分仅使用标准库，无需 pip 安装依赖。

1. 将**整个项目目录**作为 `mai-mai-order-advisor` Skill 导入主机，入口是 [SKILL.md](SKILL.md)。不要只复制入口文件，它还会引用代码与契约。具体技能目录与发现方式以主机说明为准。
2. 在主机配置官方麦当劳 MCP：`https://mcp.mcd.cn`，Streamable HTTP。凭据通过主机本地环境变量 `MCD_MCP_TOKEN` 注入，不发到聊天或写入仓库。
3. 参考 [脱敏配置示例](mcp-config.example.json)，确认主机支持相应的环境变量引用方式；该 JSON 不是所有主机通用的导入文件。
4. 按 [MCP 集成指南](MCP_INTEGRATION.md) 核对当前工具 Schema，并启用主机的写工具逐次审批。在对话中按 Skill 名称调用。

本项目不自带 MCP Server、HTTP 客户端或固定的官方字段适配器。真实工具响应由主机根据当前 Schema 规范化后交给内核。

## 不接 MCP 也能试用

在项目根目录运行：

```sh
python3 -m copilot demo
```

输出为 JSON，包含三种推荐、排除与换餐、凑券多付/少付、费用未知，以及从两道确认到待支付的模拟流程。全部使用合成数据，不需要 Token 或网络，不会真实领券、下单或支付。

也可以查看[选餐流程回放](https://imulan.top/mai-mai-order-advisor/)（[离线 HTML](docs/demos/readonly-2026-10-13/index.html)）。它保存的是 **2026-10-13 的只读查询快照**，价格不会更新，费用缺项仍待确认；页面播放不调用麦当劳接口。背景与验证范围见[验收记录](docs/validation.md)。

## 开发与接口

```sh
python3 -m copilot --help
python3 -m unittest discover -s tests -v
python3 scripts/check_project.py
```

| 入口 | 用途 |
| --- | --- |
| `python3 -m copilot compare` | 从 stdin 读取两份标准化报价，输出同车或凑券比较 |
| `python3 -m copilot recommend` | 从 stdin 读取候选、偏好及预算，输出排序和排除原因 |
| `python3 -m copilot transition` | 从 stdin 读取最新状态与事件，输出下一状态和工具意图 |
| `copilot.core` | Python 内存 API：`compare`、`recommend`、`digest` |
| `copilot.workflow` | Python 内存 API：`initial`、`transition` |

字段、单位、输出与事件定义见[内部数据契约](references/contracts.md)。它是本项目的输入格式，不是官方 MCP Schema。真实数据优先使用内存 API，使用 stdin/stdout 时也仅留在私密会话中，不归档到文件或日志。

## 当前能力边界

- **代码已覆盖的能力**：报价与优惠证据校验、三种排序、换餐排除、凑券差额解释和协作式确认状态机，均有离线回归测试。
- **已有实时验证**：门店、菜单、套餐详情、优惠查询、营养与试价的历史只读调用，详见带日期的[验收记录](docs/validation.md)。
- **仍待验证**：完整费用映射、真实优惠资格比较，以及真实领券、创建订单、订单读回和真人审批界面。接口参考价不等于已验证的最终含费实付。

缺少费用不会补零，缺少优惠条件不会猜节省金额；营养未知不会按零计算。营养排序只匹配用户指定目标，不提供医疗判断；标签匹配也不能代替过敏原核实。

状态机输出工具意图，执行与真人确认由主机负责，它不是主机级权限拦截器。写操作超时不自动重试；跨会话状态丢失时先核实官方订单状态。项目不提供自动付款、取消退款、地址新增、积分兑换、订单历史画像或隐式偏好保存。
